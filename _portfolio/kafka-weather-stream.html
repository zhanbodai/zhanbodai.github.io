What I built

  1. Producer
    Created a topic with 4 partitions and streamed daily temperature reports as protobuf messages keyed by station ID, with retries and acknowledgment from all in-sync replicas.
  2. Consumer
    Read manually assigned partitions and kept a running count, sum, average, and first and last date for each station, written to one JSON file per partition.
  3. Crash recovery
    Saved the read offset in each file. On restart, the consumer loads the saved statistics and seeks back to that offset, so messages are not counted twice.
  4. Atomic writes
    Wrote each file to a temporary path and renamed it, so a dashboard reading the file never sees a partial update.
